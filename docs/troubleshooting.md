# 故障排查

## 登录窗口无法加载

现象包括登录窗口空白、长时间停留在加载状态，或提示“登录页面加载失败”。

1. 确认网络能够访问中转服务；
2. 检查系统代理、防火墙和安全软件是否阻止 Cursor-MXG；
3. 关闭失败的登录窗口，在主界面点击 **重试登录**；
4. 如果网络刚恢复，先点击 **重试** 刷新会话；
5. 仅在你已经拥有自己的两个登录令牌时，才使用 **令牌登录**。

不要从他人处购买、复制或接收所谓“共享令牌”。

## 没有可用 Key

打开 **中转 Keys**，逐项确认：

- Key 状态为启用；
- Key 没有过期；
- Key 的分组与模型广场当前分组一致；
- Key 没有显示“本机未保存密钥”；
- 额度和服务端账户状态允许继续使用。

修改后刷新 Keys，再返回 **模型广场** 重试。

## 模型广场为空或分组不可用

1. 点击页面顶部的刷新按钮；
2. 切换到其他可用分组；
3. 检查中转 Key 是否属于该分组；
4. 确认中转服务没有临时关闭对应模型或渠道；
5. 退出登录并重新登录，以刷新账户权限。

模型和分组由中转服务动态提供，服务端下线的模型不能通过本地设置强制恢复。

## Cursor 中看不到已加入模型

1. 在 Cursor-MXG 的 **已加入模型** 中确认模型状态正常；
2. 点击 **刷新模型状态**；
3. 确认本地 CA 已初始化；
4. 确认 **接管 Cursor** 已开启，左侧状态显示 **已接管**；
5. 保存工作，完全退出 Cursor，再重新启动；
6. 在 Cursor 中新建对话后重新打开模型选择器。

已有对话可能保留旧的模型状态，优先用新对话验证。

## 本地 CA 初始化失败

- 使用 Cursor-MXG 显示的 **打开终端** 操作，并允许系统请求的管理员权限；
- Windows 上确认终端没有被安全软件拦截；
- macOS 上确认当前账户有权限修改系统信任设置；
- Linux 上确认系统证书目录和用户证书工具可用；
- 完成命令后回到应用，点击 **我已初始化，刷新** 或 **检查 CA**。

不要手动安装来源不明的 CA 文件。如果系统策略由组织管理，请联系设备管理员。

## 接管后 Cursor 请求失败

```text
Cursor 选择已加入模型
        ↓
Cursor-MXG 本机代理是否运行？
        ├── 否：重新启动 Cursor-MXG
        └── 是
             ↓
Key、分组、模型和中转网络是否可用？
        ├── 否：修复对应状态
        └── 是：刷新状态并新建对话重试
```

同时检查：

- Cursor-MXG 是否仍在系统托盘中运行；
- Key 是否被停用、删除、过期或用尽额度；
- 模型是否仍在相同分组中可用；
- 网络是否能访问模型接口；
- 防火墙是否阻止本机代理端口；
- **调用详细** 中是否记录了具体错误。

Cursor 的 **Auto** 使用官方路由，不能用于验证中转模型。请明确选择已加入模型。

## 显示“已让出接管”

这表示其他应用或用户在 Cursor-MXG 接管后修改了 Cursor 配置。Cursor-MXG 不会自动覆盖这些修改。

1. 关闭其他会修改 Cursor 代理或模型配置的工具；
2. 检查 Cursor 当前配置是否需要保留；
3. 回到 **已加入模型**，重新开启接管；
4. 手动重启 Cursor。

不要让两个接管工具同时运行。

## 退出 Cursor-MXG 后 Cursor 无法联网

接管期间退出会停止本机代理，但 Cursor 可能仍指向原代理地址。

1. 重新启动 Cursor-MXG；
2. 打开 **已加入模型**；
3. 关闭 **接管 Cursor**，让应用恢复原配置；
4. 手动重启 Cursor。

以后完全退出或卸载前，先关闭接管。

## 自动更新失败

1. 打开 **系统设置 → 软件更新** 再次检查；
2. 确认能够访问 GitHub Releases；
3. Windows 便携版确认 `cursor-mxg.exe` 所在目录可写；
4. 确认磁盘空间充足，且安全软件没有隔离更新文件；
5. 仍然失败时，从[最新版本](https://github.com/xiaomayisjh/cursor-mxg-releases/releases/latest)手动下载安装。

应用会验证更新签名。签名不匹配时不要绕过验证，应重新从本仓库下载或提交问题。

## Windows 阻止安装或启动

当前安装包可能没有 Windows 商业代码签名。确认下载地址属于本仓库后：

- SmartScreen：选择 **更多信息 → 仍要运行**；
- 浏览器拦截：核对文件名和来源后，在下载记录中选择保留；
- 安全软件隔离：先核对来源，不要盲目关闭实时防护。

无法确认文件来源时，应删除文件并从 [Releases](https://github.com/xiaomayisjh/cursor-mxg-releases/releases) 重新下载。

## macOS 提示无法验证开发者或应用已损坏

1. 确认下载了与处理器一致的版本；
2. 把应用移动到 `/Applications`；
3. 按住 Control 点击应用，选择 **打开**；
4. 在 **系统设置 → 隐私与安全性** 中确认允许打开。

确认文件来自本仓库后，仍被隔离时可执行：

```bash
xattr -dr com.apple.quarantine /Applications/Cursor-MXG.app
```

## Linux AppImage 无法运行

```bash
chmod +x Cursor-MXG_<版本>_amd64.AppImage
./Cursor-MXG_<版本>_amd64.AppImage
```

如果提示缺少 FUSE，安装发行版对应的 FUSE 运行库，或改用 `.deb` / `.rpm`。当前 Linux 包仅支持 x86_64 / amd64。

## 提交问题

在 [Issues](https://github.com/xiaomayisjh/cursor-mxg-releases/issues) 提交问题时，请包含：

- Cursor-MXG 版本；
- 操作系统版本和 CPU 架构；
- Cursor 版本；
- 安装版或便携版；
- 问题发生前后的完整步骤；
- 界面中的完整错误文字；
- 大致发生时间，便于对应本机记录。

请先删除截图和文本中的敏感内容。**不要提交**密码、访问令牌、刷新令牌、完整 API Key、Cookie、私密提示词、模型回复或个人身份信息。
